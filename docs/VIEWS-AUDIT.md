# Rail list views audit (2026-11-09, branch `views-audit` from `ui`@9e12f68)

Activity, Threads, To-dos/Later, DMs, Drafts & sent and Unreads, compared with Slack's web client.

How it was checked:

- **Slack, live:** the agent-browser `whatever` profile (the test account in Hack Club Slack), in a tab of my own, read-only. While I looked, every mark/read/write endpoint was blocked with network routes (`conversations.mark`, `subscriptions.thread.mark`, `activity.mark*`, `drafts.update`, `chat.*`, `reactions.*`, `users.prefs.set`, …). Layout came from DOM dumps (class names, `data-qa`, `aria-label`, bounding boxes, `getComputedStyle`). The API params came from the tab's request log, with the token stripped. Menus were opened and closed with Escape; no item was clicked. Nothing went to disk except the class/box dumps, which were deleted afterwards. No screenshots of Slack were kept.
- **Slack, source:** build `a84662d2` (the live `_x_id` prefix). These public CDN chunks were fetched without a cookie: `client-threads-view`, `client-dms-list-view`, `client-later-list-view`, `client-saved-view`, `page-unreads-view` and the saved-for-later chunks, plus `client-boot-render`/`client-boot-shared`/`modern.vendor` from slack-datamine-plus's chunk list. Module names are cited below.
- **Clack:** the views on internal/fakeslack's new views fixtures (`Size.Views`, internal/fakeslack/views.go) and the synthetic activity feed. The views-audit workflow saves screenshots of both.
