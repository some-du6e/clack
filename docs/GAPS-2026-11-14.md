Research only. No product code changed. Two docs/EXPERIMENTS.md rows that
were out of date are fixed (listed at the end). Slack's side is the public
CDN build `2c0d02ca130f` (slack-datamine-plus, captured 2026-11-14; its five
boot chunks fetched without cookies), `fa938a086569` (2026-11-12, gap-w27's

process for each OS: the win32 `main.bundle.cjs` from the public nupkg
(sha256 `0d25eda0…`, gap-w17's copy) and the macOS one from the public arm64
zip (sha256 `9346dff7…`, karim-1113c's copy). Offsets like `@1144516` are

Windows 11 and on the latest macOS. Since 2026-11-13 00:24 UTC Karim runs

## The gaps, most visible first

Size: **S** is under an hour, **M** is 1–3 hours, **L** is more than one
agent session. "Slack" names the module that does it in build `2c0d02ca130f`
unless another build is named.

### Seen every day

1. **macOS has no desktop notifications.** `ui/notify_other.go` is still
   the nopNotifier the 11-12 doc described. On macOS the only sign of a new
   message is the Dock badge, and the bounce if the account sets
   `mac_ssb_bounce`. Slack's macOS shell shows each one through class `h0`
   (mac `main.bundle.cjs` @1160719): `new Notification({title, subtitle,
   body, closeButtonText, actions, hasReply, sound, silent, urgency, id,
   groupId, groupTitle})`. The actions are the webapp's actionButtons after
   the first, the icon is left to the app's, a show that reports nothing in
   5 s counts as shown, and a failure is logged. Electron main's
   `shell/browser/notifications/mac/cocoa_notification.mm` builds these with
   UNUserNotificationCenter, with a category for the buttons and the reply
   and `closeButtonText` as a `CLOSE_` action. Clack.app is a bundle with an id
   and an ad-hoc signature (release.yml's macos job, `codesign --sign -`). The
   11-12 doc assumed UNUserNotificationCenter needs a properly signed
   bundle. Nobody has tested that. The first step is a probe on the macos
   runner that asks whether an ad-hoc signed Clack.app gets an authorization
   answer or `UNErrorCodeNotificationsNotAllowed`. If it gets an answer,
   Slack's options map onto UNNotificationContent one to one. **L**.
2. **The Windows title bar.** Slack's main window is frameless on Windows
   and macOS (`frame: !(win32 || darwin)`, win32 @1145327). On Windows it
   asks for `titleBarStyle: "hidden"` with `titleBarOverlay: {color:
   "#00000000", symbolColor, height: 33}` (@1144516). Electron draws
   Windows-style minimize, maximize and close buttons on a transparent strip
   at the top right of the page, and the web client's top nav is the title
   bar. The top nav is built
   for it. Boot-render's top nav adds `p-ia4_top_nav--windows`, sets the
   buttons' symbol colour through `injectCustomTitlebarStyling` (`VxbD`;
   constants-white or theme-content-inv-pry), reads `wcoVisible` and
   `shouldShowWindowsOSControls`, and moves its narrow-window breakpoint out
   by 138px for the buttons (`668 + 138/j`). The app-menu button sits in
   `.p-ia4_top_nav__native_ui_spacer`, and Clack already draws that part
   (`ui/appmenu.go`). Clack opens an ordinary decorated window (`ui/app.go`
   Run: `app.Title`, `app.Size(1440, 900)`, `app.MinSize(800, 500)`), so
   Windows puts its caption bar, with the window title in it, above Clack's
   40px top nav. `ui/caption_windows.go` only colours that bar. The
   windows-applog job's `toast-shots/clack-taskbar-badge-4.png` (ci
   43552705449, ui 4fbe9595) shows a white caption reading "announcements
   (Channel) - Fake Club - 4 new items - Clack" over Clack's purple nav.
   Slack's minimum is 668×400 (@1144473), not 800×500. Gio has
   `app.Decorated(false)`, and its `hitTest` maps `system.ActionMove`
   areas to HTCAPTION (`third_party/gioui.org/app/os_windows.go`), but it
   answers only HTCAPTION or HTCLIENT. So Windows 11's Snap Layouts flyout
   (HTMAXBUTTON) is missing, and Gio draws no caption buttons. Electron's
   are `shell/browser/ui/views/win_caption_button.cc` and
   `win_caption_button_container.cc`. Chromium keeps the
   standard frame styles and takes the caption with WM_NCCALCSIZE, so DWM's
   shadow, rounded corners and Snap stay. **L**.
3. **macOS: closing the window quits Clack.** Slack's `runFromTray`
   defaults to true on every platform (mac @1118024). MAIN_WINDOW_CLOSE
   (@1148845) calls preventDefault and hides the window. Its RunFromTray
   balloon needs the menu bar icon, which the mac TrayHandler creates only
   with Slackbot Mini (`isSlackbotMiniEnabled`, the DESKTOP_COMMAND_CENTER
   feature). Without it the shell logs "Attempted to show a balloon before
   the tray icon exists" and nothing shows. The Dock icon's `activate` (@1149631) shows the window
   again. Clack's `closeToTray` (`ui/runfromtray.go`) quits when there is no
   tray icon, "as it does on macOS". So every ⌘W or click on the red button
   quits Clack. The next ⌘Tab doesn't find it, and the next start is a cold
   one. **M**, packaged with gap 4 because both change Gio's mac window.
4. **The macOS title bar.** Slack's mac window is `titleBarStyle:
   "hidden"` (@1145075) with the traffic lights at the `{x: 14, y: 22}`
   default (@1117788), and the web client moves them to `{x: 12, y: 24}` for
   its top nav (`injectCustomTitlebarStyling` writes the `trafficLightPosition`
   setting). Clack shows the standard title bar, with the window's title in
   it, above its nav. Gio's `Decorated(false)` on macOS hides the traffic
   lights too (`setWindowStandardButtonHidden` in `os_macos.go`), so this
   needs a Gio patch with full-size content, a transparent hidden title, the
   buttons kept and moved, and the nav's empty space as the drag area.
   **M–L**.
5. **Karim's glyph sweep.** On 11-13 at 20:38 UTC, in the "Also send to
   #clack" thread, Karim asked for every hand-drawn Slack glyph to be found
   and drawn properly. The icons package is held to Slack's SVGs, with 290
   icons in `slackRef` (TestIconsMatchSlack, light and dark, 1x and 2x) and
   29 in `clackOwn` with reasons. 25 glyphs outside it are drawn from descriptions or by eye
   and held to nothing. The ones seen most are the emoji picker's ten
   category tabs (`popups/emoji_glyphs.go`: "drawn here from our own
   geometry (matched by eye to Slack's tab icons)"), shown every time the
   picker opens. Then `composer/autocomplete_view.go`'s drawHashIcon,
   drawLockIcon, drawArchiveIcon, drawPeopleIcon, drawSlashGlyph,
   drawArrowGlyph and drawReturnGlyph, and `composer/chrome_icons.go`'s
   crIconEmojiHover, crIconSend and crIconCheck ("Drawn from the spec's
   descriptions"). The rest are `popups/profile_card.go`'s pfHeart ("two
   round lobes"), `huddleui/invitewin.go`'s hourglass,
   `huddleui/connection.go`'s connIcon (TgjK's four bars),
   `ui/focus_mode.go`'s focusTelescope and `slackc/kit/controls.go`'s
   ctlCheckMark. Slack's set (`build/icons.json`, 727 icons in
   2c0d02ca130f) has `search`, `emoji` and the `emoji-nature`, `-food`,
   `-travel`, `-activities`, `-objects`, `-symbols` and `-flag` category
   icons, `channel`, `lock`, `archive`, `user-groups`, `slash`, `arrow-up` /
   `arrow-down`, `enter`, `send-filled`, `hourglass`,
   `status-slackbot-filled`, `check` and `checkbox`. Where Slack draws a CSS tick or an
   icon-font glyph instead, the port follows that. The 29
   clackOwn names need the same check against the 727. **M**.
6. **Long links** (Karim, 11-13 17:27 UTC; at 20:39 they pointed at a
   message slug for the look). Slack's composer shortens a pasted link
   longer than 140 characters. When the paste is one link whose text is its
   URL, boot-shared `rBgP` (prepareDeltaForPaste) puts client-boot `A862`
   truncateUrl's text in its place and keeps the link. truncateUrl calls
   truncateSmart(url, 140, "[…]"), which keeps the host first, then the path,
   query and fragment, and cuts the middle to "[…]". A URL with two or more
   "?", or with no path and no fragment, is left alone. `Jk4U`
   isOpTruncatedLink knows the shortened insert, and the send (`VxMM`) writes
   `{type: "link", url, text, truncated: true}`. Editing such a message turns
   it back into a link slug labelled with that text (`V/2c`; the canvas-style
   input's `GyHH` truncatedLinkToSlug does the same), and messages draw the
   link's text as it is (`+W5o` getLinkContents). Clack's composer and richtext have no
   truncation anywhere, so a pasted 300-character URL goes out whole and
   fills three lines in everyone's Slack. **S–M**.
7. **GIFs in messages don't play.** `internal/imgcache` animates only up to
   160px (`MaxAnimPx`; "a large GIF stays its first frame") to keep memory
   down. Slack plays them. File images use `animatedSrc` (`OhSF`), and
   attachments and image blocks carry the animated `src` next to a
   `deanimatedSrc` (`FnNq`). Only with Accessibility > Allow animations off
   (`a11y_animations`, `suppressAnimations`) does Slack draw the `deanimate`
   still, with an Expand button on GIF and PNG files (`gaA3` renderExpand,
   the zoom-in icon). GIFs are common in Hack Club channels, so this shows
   most days. A GIF should decode at its drawn size, only while it's on
   screen, inside the 768 MiB soft limit (docs/MEMORY.md). **M**.
8. **The Windows notification area and taskbar.** Clack's tray icon never
   changes, its tooltip is "Clack", and its menu is Open Clack / Quit Clack
   (`desktop/tray_windows.go`; `cmd/clack/main.go` starts it, nothing calls
   SetTooltip). Slack's TrayHandler (win32 @1177993) switches between
   `slack-taskbar-{rest,unread,highlight}.ico` by getTrayStateFromUnreadsInfo.
   Its tooltip is "You have {n} notifications", "You have unread messages" or
   "No unread messages". Its menu (createTrayMenu @1179887) lists the
   workspace (a click switches to it and brings Slack forward), a separator,
   Launch Control ▸ (Launch on Login, then Show Slack Immediately / Keep in
   Background radios), Check for Updates, Preferences (Ctrl+,), the
   troubleshooting item, and Quit (Ctrl+Q). A left click foregrounds the
   app. Slack's taskbar jump list (createJumpList @1174947) has Workspaces
   (`slack://open?team=…`) and Tasks › "Move Slack to Current Display"
   (`slack://app/?action=reset-window`). Clack has none. And Slack mutes the
   message sound while Focus Assist is on. checkNotificationState("sound
   playback") returns `!isFocusAssistActive()` (@1004328; `a6` @924384,
   mode 1 "priority only" counts unless Slack has priority, mode 2 "alarms
   only" always). Clack's `notifyMessage` (`ui/notify.go`) checks only
   `mute_sounds` and Slack's own DND, so the knock plays through Windows'
   Do not disturb. **M**.
9. **The window forgets where it was.** Slack saves `mainWindowSettings`
   (bounds, maximized, fullScreen, restorableState) and opens there (win32
   @1144440; restorableState and the display check @1147120 in the mac
   build). Clack opens at 1440×900 wherever the OS puts it, every launch. Gio
   has no window position option. **M**.
10. **Activity leftovers** (W25 never started; docs/ACTIVITY.md "Not done").
    The list's 8px lead-in (`--activity-first-item-lead-in`, which also keeps
    Slack's VIP header from sticking at scroll 0) shows on every open. The
    rest are the importance icon, agent entries' Block Kit actions (`5465`'s
    `activity_actions`), the In picker's suggestions with no query, the tab
    strip's More, "Discard changes?" when closing Create a new view, the
    sort button's new badge and the bulk buttons' tooltips. **M**.
