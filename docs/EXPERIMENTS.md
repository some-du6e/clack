# Slack's experiments in Clack

<!-- Generated from the experiments inventory (branch experiments, 2026-11-10); the method below. -->

Slack turns features on per account with experiments. Clack should behave the way
Slack's desktop client does in whatever group the account is in. This is the inventory
of the Hack Club test account's assignments against Slack's own client code, the
plumbing that lets Clack and its plugins follow them, and the work left, by area.

## Method

1. **The account's assignments.** One read-only `experiments.getByUser` call (the Python helper; Go's TLS fingerprint signs the account out): **1,609 experiments in 42 groups** (on 1290, treatment 125, off 81, control 70, treatment_a 3, …); 831 user, 690 team, 88 visitor experiments. Names and groups only; nothing else from Slack is stored.
2. **Slack's client.** The public CDN build `4d0c78085232` (2026-11-10): all 4,492 chunks from slack-datamine-plus `build/chunks.txt`, fetched from `a.slack-edge.com/bv1-13-br/` without cookies. Each rspack chunk is split into its modules with a small JS tokenizer, and every quoted experiment name is matched to the call it is passed to. A name counts as **read** when it goes to:
   - Slack's experiment selectors (GantryV2 `client-boot` module `HWuB`, webapp `modern.vendor` `gXii`, sign-up `get-started` `149N`): `_Z` getGroupForUser, `ze` the same without logging the exposure, `KK` getAssignmentByName. **getGroupForUser answers null for an experiment the viewer is not assigned to**, so `"on"===g` is false and `"control"!==g` is true for it;
   - the exposure loggers (`jRif`/`aj0q`/`iP/w` `K`);
   - session toggles (`NEu9`/`YRcd`/`sZD8` isToggleEnabledForSession `fW` / getToggleGroupForSession `B9`, the `LRGb` table, the `MrD9` constants): the group is latched in `localStorage` `TOGGLE_STORAGE-<name>` for the session;
   - doesToggleGroupMatchForAnyTeam (`3jDn`/`JqeO`/`njiC` `_`).
   Names that only appear as a Logger label (`new Logger("…")`), an analytics element or enum, a pref key read through the pref getter, or an API field are not reads.
3. **Cross-check.** slack-datamine-plus `experiments.json` lists 560 of the account's names; the scan finds every one of them as read, plus the ones it misses (names read through constants and session toggles).
4. **Classification**, by reading each read's module and function:
   - **A**: UI or behaviour the desktop client changes that applies to Clack;
   - **B**: read by the client, but only for things Clack lacks or that don't apply (reasons below);
   - **C**: not read by the client at all (server-side, email, mobile).

## How Clack follows them

- **core** keeps what Slack's `experiments` store keeps (client-boot `RIWm`): experiments.getByUser's records, whole (`ExperimentAssignments`), plus a forced layer, the way Slack's `overrideExperimentAssignments` replaces a group. `Experiment(name)` is the group every check reads ("" when not assigned, Slack's null). `SetExperimentGroup` / `SetExperimentGroups` force groups ("" reads as not assigned), `ClearExperimentGroup` gives the server's back; every change emits one `experiments` event, the sidebar is rebuilt and every check reads the new group on its next frame (internal/core/experiments.go).
- **Taut's mirror** serves the `experiments` slice as those records. After every change to the plugins' state patches the runtime compares the patched slice with the raw one and sends Go the groups that differ (internal/taut/js/03_redux.js `tellGoExperiments`), and the host forces them in core (internal/taut/experiments.go). Anything that changes what Slack's code would read takes that path, with no per-plugin code: Taut's `api.experiments` (Taut's Experiments, BringBackSlackbot) and a raw `redux.patchSlice('experiments', …)` (Slick's Experiments). When a plugin stops, or the runtime dies, its groups go back to the server's.
- **Slack's selectors** in the runtime answer like Slack's (`getGroupForUser`, `getGroupForUserWithoutExposure`, `getAssignmentByName`, `getAllExperimentAssignments`; null when unassigned), and Clack's own checks are a module source, `clack-experiment-reads`, written the way Slack's modules read experiments (`"on"===(0,x.getGroupForUser)(s,"name")`). Both plugins scan module sources for those calls to offer each experiment's groups, so their tabs list the experiments Clack reacts to and the groups it compares. `core.ExperimentReads` is that list; `TestExperimentReadsListed` keeps it in step with the code.
- **The Experiments plugins** (Library: Taut `taut-Experiments.js`, Slick `slick-Experiments.js`) each add an Experiments tab to Preferences with all 1,609 assignments, search, filters and a group menu per experiment. An override saved there reaches core at once and flips Clack's behaviour live: `TestExperimentsPluginsDriveClack` (internal/ui, `.github/workflows/experiments.yml`) installs the published bundles over fakeslack and checks that forcing `sidebar_section_search` off removes the section menu's "Search in this section", and that turning the plugin off brings it back. Their "Reload" buttons aren't needed in Clack; overrides apply live. Slick's description promises "other dev-only features", but its code (34f2c25) only has the experiments tab.

### Notes

- Clack checks 15 experiments the account is **not assigned to**, so Slack reads null for them and so does Clack (none are in its defaults): `activity_in_home_prototype`, `activity_with_sidebar`, `agentic_ia`, `channel_ia_header_refinements`, `huddles_raised_hand_queue`, `meeting_assistant`, `ml_fuzzy_match_beyond_word_boundaries_v2`, `programmable_sidebar_dm_history`, `scheduled_huddles`, `session_channels_code_tab_pr`, `session_channels_gh_wo`, `slash_command_failed_dedupe`, `suggested_sections_auto_sort_killswitch`, `support_lots_of_agents`, `unified_global_triage`.
- `reskin_custom_responses` is assigned (`on`) but **no longer read** by this build: Slack draws every custom response the reskinned way without asking (BaseMessageAvatar's TeamIcon, ffJE's `isCustomResponse` for the team's name, t6PO's `customResponseInfoBadgeIcon__mN56C` badge, MessageLabels' tint with no label line, ReplyBarAvatar's team icon). Clack dropped its gate too (2026-11-10, Karim's call; core's `CustomResponseReskin` is gone): custom responses always draw that way (ui/messages/custom_response.go), and BringBackSlackbot's override of the experiment no longer changes them, in Clack as in Slack.
- `agentforce_deprecation` is read by Clack's rail (internal/core/rail.go) only to hide an Agents tab that needs Agentforce access, which Hack Club doesn't have; it's B.
