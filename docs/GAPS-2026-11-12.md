### How it's counted

`python3 -I docs/gaps/score.py [ref] [-v]` re-runs the count at any commit,
and `-v` prints every open check. The method is the 11-11 doc's, with one
fix. Its grep for unfinished features matched `" + AppName + "` and the
literal words "in Clack" or "in yoloslack". gap-w4 rewrote those strings as
`"Workflows aren't supported in "+appName`, the lower-case constant in
`popups/i18n.go` and `views/i18n.go`. Six messages fell out of the count
while still in the code: the team menu's Tools > Workflows and Analytics
toasts, "Emoji packs aren’t available in Clack yet.", the Availability nav's
"… preferences aren't available in Clack yet", and the External and
Invitations tabs' empty states. The script now takes either spelling and
joins the pieces back into one string before it reads the message. It
still reproduces the old baselines: 481/622 at 3a5a037 and 583/690 at
b9049a0e (the 11-11 doc's 584 included that branch's own row fixes).

The generic "Not supported yet" toast stays out of the count, as the roadmap
had it. Five buttons still show it (gap 12).

## The gaps, most visible first

Size: **S** is under an hour, **M** is 1–3 hours, **L** is more than one
agent session. "Slack" names the module that does it in build `2cd9270e786c`
unless another build is named.

### Seen every day

1. **No desktop notifications on Windows or macOS.** Slack's shell shows an
   Electron `Notification` for each message notification and huddle invite
   (`main.bundle.cjs` @1148252, class `E3`; on Windows that's a WinRT toast,
   the prefs dialog's `notificationMethod` "winrt"). Clack's notifier is
   D-Bus on Linux and `nopNotifier` everywhere else (`ui/notify_other.go`),
   so on Karim's Windows 11 machine a DM or mention plays the sound and
   shows nothing. Huddle invites' Join / Decline banners don't show either.
   Clicking a toast should open the conversation. While Clack runs, the
   toast's Activated event can do that. A click from Action Center after
   Clack quit needs a COM activator or a protocol Clack owns, and `slack://`
   is Clack's only when the installer's "Make Clack the default for
   slack:// links" box is ticked, which it isn't by default. **M** for
   Windows, **M** again for macOS (UNUserNotificationCenter, which wants the
   signed bundle). Files: a new
   `internal/ui/notify_windows.go`, `ui/notify_other.go`, a new
   `internal/desktop/aumid_windows.go`, `packaging/windows/clack.iss` (the
   Start menu shortcut needs an AppUserModelID for toasts to show).
   PREFS-AUDIT "Notifications" now records it.
2. **Closing the window quits Clack.** **Done on Windows by gap-w18**
   (below). Slack's settings default
   `runFromTray` to true (`main.bundle.cjs` @1104712, `runFromTray:!0`). On close,
   MAIN_WINDOW_CLOSE (@1137077) calls preventDefault and hides the window
   unless the setting is off or no workspace is signed in, then shows the
   RunFromTray notice once: a tray balloon, "Why didn’t Slack quit?"
   (TrayHandler `_X` @1174664, text @1180282, Electron's
   `Tray.displayBalloon`). So Slack keeps running in the notification area
   and keeps notifying. Clack had the tray icon (`desktop/tray_windows.go`)
   but quit on close, and Preferences > Advanced greyed "Leave app running
   in notification area when the window is closed". NATIVE.md said Gio
   can't intercept the close button. It can: Gio's `ClosingEvent.Abort`
   exists (`third_party/gioui.org/app/doc.go`). What was missing is Clack's
   handler and a way to hide the window on Windows. Chromium hides with
   `SetWindowPos(SWP_HIDEWINDOW | SWP_NOACTIVATE …)`, not
   `ShowWindow(SW_HIDE)`, which activates another window
   (`HWNDMessageHandler::Hide`). gap-w18 found one more thing: Clack ran
   posted work (the backend's events, notifications) only inside frames,
   and Gio on Windows draws no frames for a minimized window, so a
   minimized Clack handled no events until it came back. A hidden one
   would have been the same. Posted work now runs on Gio's wake-up event
   too. **gap-w18:** Gio patch 13 (`Window.Hide`, `ActionRaise` shows a
   hidden window, hidden windows draw no frames), `internal/ui/runfromtray.go`
   (the close handler, the balloon once, `drainIdle`), `Tray.Balloon`,
   the Advanced row a real checkbox where a tray runs, `Quit` sets
   isQuitting. Still different: macOS hides Slack's window on close too
   (the same handler; the Dock brings it back), and Clack quits there;
   Linux Slack has a tray icon and Clack has none, so the row stays greyed
   there. Slack's tray menu is the workspaces, Launch on Login, Check for
   Updates, Preferences, Troubleshooting and Quit (`createTrayMenu`);
   Clack's is Open Clack and Quit Clack.
3. **No taskbar badge or flash on Windows.** Slack sets the taskbar overlay
   icon from `resources/unread-badge` (one image per count to 99, one past 99,
   cleared at 0,
   tooltip "You have unread messages", `setOverlayIcon` @1163233) and
   flashes the frame when a notification arrives. Its Notifications page
   has a Windows block, WindowsAppearancePref (prefs-dialog `AM7V`, after
   SoundAppearancePref): "Flash window when a notification is received"
   (Never, When left idle "(inactive for at least 10 seconds)", or Always;
   `win32.windowFlashBehavior`, default idle), "Deliver notifications via…",
   Notification position and Display. Clack's badge is macOS only
   (`desktop/dock_darwin.go`; `dock_other.go` is empty), with no flash and
   no Windows block. **M**. Files: a new `internal/desktop/taskbar_windows.go`
   (ITaskbarList3), `desktop/dock_other.go`, `ui/dock.go`, `ui/notify.go`, a
   new `ui/prefs_win_appearance.go`.
4. **No clip buttons in the composer.** Slack's composer bar has the video
   and audio clip buttons after @ and a divider (TextyButtons `Ozua`, gated
   on the team prefs `allow_video_clips` / `allow_audio_clips` and on
   `window.MediaRecorder`, Jg9Y `yD` / `hP`). Electron has MediaRecorder, so
   Karim's Slack shows them in every composer. Clack hides them the way
   Slack does without a recorder (COMPOSER-AUDIT "Clip buttons"), because it
   has no recorder, encoder or clip upload ("Recording clips"). **L**: audio
   (AudioPopover, `audio_message.m4a`, subtype `slack_audio`) and video are
   one package each. Not packaged below.
5. **The deleted-message row sits 4px left in channels.** Slack pads it like
   a message, `.p-message_pane_message__message .c-message_kit__tombstone
   {padding:8px 20px}` (client-boot-styles), so the trash square lines up
   with the avatars at x 20 and the text with the bodies at 64.
   `tombstoneLayout` (`messages/row.go`) uses the thread pane's `mt.padX` 16
   and `mt.contentX` 60. Measured in compact-shots' `clack-clean-dark.png`
   against `slack-channel-clean-dark.png`: square at x 16 vs 21, text at 60
   vs 65. **S**. File: `internal/ui/messages/row.go`. MESSAGES-AUDIT
   "Deleted message".
6. **A user group mention in a thread reply doesn't notify.** Slack's
   checkForMentionInMessage counts a group the viewer is in. Clack's
   `replyMentions` (`ui/notify_threads.go`) checks only `<@self>` and
   `<!here>`. The THREADS-AUDIT row said core didn't know the viewer's
   groups. It does now: store `MyGroups` (usergroups.membership,
   subteam_self_added / _removed) and `Store.InUsergroup`, which
   `core.MentionsViewerDirectly` already uses. **S**. File:
   `internal/ui/notify_threads.go`. This matters once gap 1 lands; today
   only Linux shows these.
