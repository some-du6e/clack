# internal/taut: what UI owners call

`internal/taut` runs Taut plugins unmodified. It covers the `$taut` module, the plugin manager, the full TautAPI over `internal/core`, and the Preferences > Taut model. The TautAPI itself is JS (`internal/taut/js/*.js`, Clack's own implementation of Taut's contract) and runs on jsrt next to the plugins. Go owns files, config, secrets, lifecycle, the Redux mirror ([PLUGINS-state.md](PLUGINS-state.md)) and the APIs below. Without an enabled plugin, none of this starts a JS engine. Every check below is an atomic load.

## Wiring (ui root)

```go
t, _ := taut.New(taut.Options{App: app, UI: taut.UIHooks{
	Attached:    func(b *taut.Bridge) { slackc.SetBridge(b) },   // b also has RenderPreferencesTab / RenderEditor / RenderDataPanel
	Deliver:     func(root uint64, tree []byte) { slackc.Deliver(root, tree) },
	SetPatched:  slackc.SetPatched,
	CallGo:      slackc.CallGo,
	SetStyle:    slackc.SetStyle, RemoveStyle: slackc.RemoveStyle, // user CSS is key "user"
	Overlays:    func(o []taut.Overlay) { /* draw each o.Root (bit 52) as a modal layer */ },
	PreferencesTabs: …, Invalidate: w.Invalidate, Toast: …, OpenPreferences: …,
	ThreadPane:  …, Input: …, SetLocalDraft: …, SwitchAccount: …,
	OnDocument: slackc.SetDocument, OnDocumentProps: slackc.SetDocumentProps, // plugin DOM in body/head, <html>/<body> props
}, PickFiles: nativeFilePicker /* <input type=file>; nil = inert */})
defer t.Close()
```
`taut.New` reads `~/.config/clack/taut/` (config.json, user.css, plugins/*.js and their cached metadata). After `core.Boot` it starts the enabled plugins that run in this workspace. Hack Club–only plugins run only on the Hack Club grid (E09V59WQY1E / T0266FRGM).

If the JS engine traps, taut starts a fresh runtime on next use and restarts the plugins that were running.

Function ids: taut tags its own `{"$fn"}` / `{"$gofn"}` ids with bit 51 (`taut.IsTautFn`). `Bridge.Call` routes both kinds.

## Thunks: `taut.Dispatch`

Route Slack's named actions through `taut.Dispatch` where the UI would call core:

```go
_, err := taut.Dispatch(ctx, t, "currentUserStartedTyping", map[string]string{"channelId": ch, "threadTs": ts},
	func(ctx context.Context, a map[string]string) (any, error) { return nil, app.Typing(a["channelId"], a["threadTs"]) })
```
When no plugin patches the name, this is just `native(ctx, args)`. When a plugin patches it, the plugins' wrappers run in JS, and they can change the args, skip native, or change the result. Pass Slack's argument shape and call it off the UI goroutine. Thunks in `taut.SyncThunks` (menus, autocomplete) run their native on the JS thread, so keep those natives pure and fast. `t.RegisterThunk(name, fn)` sets the native that runs when a plugin dispatches the thunk itself. Defaults over core exist for the ones marked *taut*.

## Composer, messages and members

- `t.ComposerButtons()`: true when plugins added composer buttons. Render `slackc.Render(gtx, "TautComposerButtons", Props{"placement": "native"|"end", "context": taut.ComposerContext{…}}, nil)`. Each button is an `@ComposerButton` node with `{id, icon, label, pressed, onClick, tooltip}` (children: a custom icon). A thread composer's broadcast checkbox is `ComposerContext.Broadcast{Active, ChannelType, Set: t.Func(…)}`.
- `t.HasSendChecks()` / `t.SendCheck(ctx, composerCtx)`: run before sending. `false` keeps the text in the composer.
- `t.HasSendTransforms()` / `t.TransformSendBlocks(ctx, blocks)`: apply to the Block Kit of every send, edit and schedule.
- `t.HasLinkTransforms()` / `t.TransformLink(ctx, url, "paste"|"link-dialog")`: links pasted or added in the link dialog.
- `t.HasInlineMarkup()` / `ParseInlineMarkup` (offsets in runes), `SerializeInlineMarkup`, `EscapeInlineMarkup`: replace the composer's `*bold*` shortcuts (RealMarkdown). viewContext values are Slack's names: `MESSAGE_PANE`, `THREADS_FLEXPANE`, …
- Pending files (files.go): set `taut.PendingFiles` (list), `taut.RenamePendingFile` (the `updatePendingFile` action), `taut.PersistPendingFile` (maybePersistPendingFileData) and `taut.EditFile` (editFileApi) once, before the runtime starts, and call `t.PendingFilesChanged()` when attachments change. They serve `pendingFileUploads` and `files`. Unset, plugins see no pending files.
- Shaped natives: some Slack components have a JS shape beyond their name (04_react.js `SHAPES`). TextyInput is `memo(class TextyInput)` with Slack's `{instance: {quill}}` on its ref. Its owner feeds the Quill with `__taut.feedNative('TextyInput', props => ({state: {length, index, selected}, props: rest}))` from a prelude (ui/composer does).
- `t.SetComposerDraft(taut.ComposerDraft{DraftID, Channel, ThreadTs, Broadcast, Ops, FileIDs, Cursor})` while you type (Slack's fastLaneDraftUpdate: 150 ms debounce, leading and trailing) and `t.ClearComposerDraft(draftID)` on send: the composer's live draft in `drafts.unifiedDrafts[draftId]` (HaikuWarning's banner reads its ops). No-ops until the runtime runs.
- `t.RegisterInput(where, true/false)`: register composers with Slack's `{viewContext, channelId}`. Answer `UIHooks.Input` ops `isEmpty`, `getContents`, `setContents`, `focus` and `insertText` (`getInputProxy`).
- `t.SetEditing(windowID, ch, ts, open)`: call when an editor opens or closes. `patchMessageText` leaves the message being edited unchanged.
- `t.SlicePatched("messages")` → `t.MessageView(ch, ts)` (core.Message, ok) and `t.InjectedMessages(ch)`. `t.SlicePatched("members")` → `t.MemberView(id)`. `t.SlicePatched("channels")` → `t.ChannelView(id)`. `t.ChannelRestriction(ch)` → read-only / thread-only. These never block: they return ok=false until the patched value is computed, then `Invalidate` fires. A view's conversion is kept until the value, the message in core or what the conversion read changes. Each conversion records the members, conversations and files its Doc read (`core.Message.Refs`: a file's owner, a huddle's people, a message slug's author and channel, a DM's partner, a work object's people, a channel mention, a tab slug's channel and the canvas that titles it). User mentions aren't recorded: richview draws their names from the store as it lays them out. A profile change, a channel change or a channel's tabs (`user`, `conv`, `conv_removed`, `tabs`) convert again only the messages that read them (`core.RefsChanged`), and only when the event changed what Docs read (`Event.SameNames`: a status, a topic or a bookmark changes nothing). A names pref (`display_real_names`, `hidden_users`: `Event.NamePrefs`) converts again the messages that read any member; the highlight words or `emoji_mode` (`Event.DocPrefs`) convert every message; other prefs none. A change only redraws when a conversion it hit is still cached, and the index forgets conversions whose views went. `t.MessageViewConv(ch, ts, fresh)` also returns the conversion's serial: a list re-applies a view converted again even when only a name in its Doc changed. The unpatched lists do the same with their own models (ui/messages hub `reconvert`, through `core.App.StoredMessage`, whose reads don't count as a view's: `store.Peek`); a load that was out during a change converts its answer again when it lands.
- Background traffic costs no frame and little JS. A change redraws only when the UI read the changed view within a second of its latest read (a channel left, a member no row draws now: marked stale, fetched again when next read). Member and presence changes go to JS only for ids it read since their last change (or all, once it listed the slice's keys), and while an invalidate task waits behind a busy runtime later batches join it. Raw passthrough events (badge counts, a thread marked read or its state, Slack's raw pref_change, a followed thread's notification) re-convert nothing; a names event with ids, an emoji change, a canvas's or list's content re-convert the conversions that read them (Message.Refs records members, conversations, files, bots and the emoji a message used, its reactions' too), and only the highlight words, emoji_mode, experiment groups, the viewer's user groups and a resync every message. The worker decodes only values whose bytes changed. Lists and rows re-read their views when `t.ViewEpoch()` moved since their last read, not only every 250 ms: the one frame a new value asks for came inside that window, and with quiet frames (an animated emoji's ticks lay nothing out) nothing laid the window out again.
- A message's view and its readiness: `t.MessageViewState(ch, ts, fresh, need)` (messages/taut.go applyView). A view is ready when JS gave it after every change marked to that message (an event's: the mirror's invalidateMsg), to its channel's bucket as a whole and to the slice, none queued for JS, and after the mirror handled core's event `need`: the `core.Event.EmitSeq` of the event that wrote the row's copy, or `App.EmitSeq()` when the load that read it returned (the hub's entry.seq). A plugin-wide refresh (`api.redux.refresh`: Message Logger's after every edit or delete it logs) changes no message: it makes every view stale (fetched again) but holds no row, whose cached view is JS's copy of the same revision. A row whose view isn't ready draws its new source, and a viewed row keeps drawing its view until JS's copy of the new revision comes. When readiness turns true with nothing else changing, taut asks for the frame: a fetch that brings back the bytes it had sent but puts the message's view past its marks moves `ViewEpoch` and calls `Invalidate`, and so does the mirror passing the smallest `need` a read waited on. A change only a load brings (core's poll writes the newest page while the socket is down) gets an event's marks: the hub calls `t.MessagesChanged(ch, tss)` for the messages whose copy the load changed, before the model takes the answer. Merged with activity-live-msg (α.109): `core.Event.Seq` is its change table's position, not the emit order. Never feed it to `need`: it is far below what the mirror handled, so the wait is off. Every path an event takes into a list carries the event's `EmitSeq`, never 0: hub.apply's upsert, notePlace and keepLive's place upsert (an update of a message a load out didn't hold yet), and keepLive's reaction path. TestRowWaitsForTheMirror (reaction, edit, place) and TestKeepLiveTakesTheEventsEmitSeq fail with `Event.Seq` or 0 fed in. `emitIf` numbers an event only once its check has passed, so `App.EmitSeq`, a load's need, is the number of the last event actually sent: a refused one leaves no need the mirror can't reach. A subscriber that fell behind has events dropped and gets a resync with the next event core emits, which claims everything emitted before it. Until then a need past what it handled waits, as it did before the merge. A reaction during a load lays its reactions over the answer's copy instead of putting back the list's copy whole: a dropped model's copy missed the edits made while it was out (TestDroppedModelKeepsItsEditUnderAReaction). `messages.Live` skips a dropped model, so Activity never draws a re-adopted model's older revision (TestActivityLiveDroppedModel). msg-latency: put the view fetches on the in-order lane, so no fetch queued before an invalidate runs after it. postInvalidate's joining lets a later invalidation ride a task a send pulled ahead. The dropped model's reload branch sets `m.epoch = p.Epoch`, or every older page after it is turned away. The fetch's same-bytes shortcut compares the checksum of the bucket assembled whole. TestViewedRowGoesBackWithOnlyInvalidateFrames and TestDroppedModelPagesBackAfterItsReload guard these.
- `t.ActionablePatched()` / `t.ActionableMessage(ctx, ch, ts)`: edit/delete checks, the up arrow and the editor see this message.
- Components rendered inside a thread pane pass `$pane: {channelId, threadTs, windowId}` in their props (`api.threads.usePane`), and the pane answers `UIHooks.ThreadPane` ops `loaded`, `topReply` and `jumpToReply`.
- Each message list (a channel, a thread pane, either in the split view) draws its patched components as a slackc pane (`slackc.Pane`). Their roots are the pane's own, per window, as each of Slack's panes is a React subtree with components of its own. A reply also sent to the channel shows in the channel's list (Slack: BaseMessageList's MessageWrapper) and in its thread pane (ThreadsFlexpane's ThreadReply → ThreadReplyGeneric). It used to share one MessageWrapper root between the two, which got each pane's props in turn and rendered again every frame. A conversation's composer draws in its list's pane (`composer.LayoutIn`) and a Threads view card's in `threads:<thread>`: two composers of one thread shared an InputContainer root, and a plugin's wrapped `prepareAndSendMessage` called back the composer drawn last, so a reply sent from the other was lost.
- Thread replies: Clack's thread pane draws a reply as ThreadReplyGeneric with no MessageWrapper, as Slack's thread pane renders ThreadReply → ThreadReplyGeneric (modern.vendor; MessageWrapper, boot-shared EXGU, is BaseMessageList's alone). ThreadReplyGeneric gets what ThreadReply hands it in the thread flexpane: messageContainerType "Thread", blocksContainerContext "thread", isSingleThread, adjacent only under the Clean theme, className `c-message_kit__message c-message_kit__thread_message` (`…--pending` for a send on its way), showShareButton, and no-op clearHighlight, onBackgroundClick and onMediaPlaybackInProgressChanged. So a MessageWrapper patch (ShowRealUser's) doesn't reach thread replies, as in Slack; a ThreadReplyGeneric patch does. Both panes draw MessageBackground.

## Settings (Preferences > Taut)

`t.Settings()` returns the categories (Messages, Message Box, People, Privacy, App, Fun, Other) with each plugin's name, mrkdwn description, authors, enabled/running state, error, option problems, options and data flags. It also carries the custom CSS box, a config.json error and plugin tabs. Option kinds map to controls: boolean → toggle, number → number field (Min/Max), string → text field, select → dropdown, list → rows, color → picker, json → code box, secret → password field (`t.Secret` / `t.SetSecret`). `HasEditor` means a React editor, rendered with `Bridge.RenderEditor`. `HasDataPanel` means the plugin's panel, rendered with `Bridge.RenderDataPanel` while it runs, and remounted when `RunID` changes. Actions: `SetEnabled`, `SetOption`, `ResetOption`, `SetSecret`, `Import(code, replacingID)`, `InstallURL`, `Remove`, `ClearData(id, "storage"|"cache")`, `SetUserCSS`, `ReloadConfig`. `t.Subscribe()` signals changes.

Files: `config.json` (Taut's format: only set options), `user.css`, `plugins/<id>.js` plus `.meta.json`, `storage/` (api.storage, api.Cache, localStorage), and the separate 0600 secret store (`secrets.json` for opt.secret values and accounts, `secrets/` for api.secrets).

## Extensions (other plugin systems on this runtime)

`t.Extend(taut.Extension{Name, Install, Prelude, Ready, LocalStorage, LocalStorageKeys})` adds a plugin system to Taut's runtime: `Install` registers host functions and `Prelude` runs after the TautAPI in every fresh runtime (the internals are on `globalThis.__taut`, the base API on `globalThis.TautAPI`), `Ready(rt, restarted)` runs once the runtime is attached (restart what ran after a crash), and `LocalStorage` serves read-only virtual keys that never reach disk. `t.JS()` starts the runtime on demand; registering an extension doesn't. `t.DataList/DataRead/DataWrite/DataDelete/DataClear` give extensions namespaces in Taut's data store. internal/slick is the user ([PLUGINS-slick.md](PLUGINS-slick.md)). `ComposerContext.Blocks`/`Text` carry the outgoing message to send checks.

## api.huddles (native)
`internal/ui/huddleui` feeds the TautAPI's huddles from the native session (`internal/taut/huddle.go`):
- `SetActiveHuddle(callID, channelID, selfAttendee, selfUser)` → `onActiveHuddle` / `getActiveHuddle` and the `getActiveHuddleCallId` / `getActiveHuddleChannelId` selectors.
- `HuddlePeerMessage(huddle.PeerEvent)` → `onPeerMessage` listeners get `{message, kind, senderAttendeeId, selfAttendeeId}`, with protobuf-es field names (`reacji`, `muteRequest`, `fromPeerIdString`…) for the `data-channel`, `awareness-sync-channel` and `transcript-catchup` topics.
- `SetHuddlePeers(attendee → user)` → the `peers` slice (`byId`, `leftById`), so `getAttendeeUserId` works.
- `SetHuddleReaction(f)` → `sendReaction` / `sendReactionMessage` send a reacji through Chime.
- `ENABLE_EVENT_LOG` / `DISABLE_EVENT_LOG` set `huddleEvents.enabled`.
