# Slack's i18n model, and Clack's

Evidence: Slack's public web client, CDN build `a84662d2d135` (captured
2026-11-08; chunks named in slack-datamine-plus `build/chunks.txt`), fetched
without cookies. Module ids are client-boot's unless noted.

## How Slack loads strings

- **Bundles.** One JSON file per locale on the CDN,
  `https://a.slack-edge.com/bv1-13/gantry-v2-translations_<locale>.gantry-v2.<contenthash>.min.json`.
  The names aren't in the webpack manifest. The client page's inline script
  builds them: `window.translationMap = {locale: wd.cdn + file}` (wd.cdn
  is the page's `data-cdn`). `7LPv ensureTranslationData(locale)` fetches
  `translationMap[locale]` with `credentials: "omit"` (dev and gov builds
  use "include") and hands the JSON to `C91c addTranslationBundle`. en-US
  is never fetched: `ensureTranslationData` returns early for it.
- **Shape.** `{namespace: {key: translation}}`, 624 namespaces and 43,014
  strings in es-ES. A value of `0` means "same as the source" (brand names,
  short words). The en-US bundle has every key, all `0`.
- **Keys.** `new I18n("prefs").t("Language")`: the namespace is the I18n
  instance's (`t(src, {ns})` can override it). The key is the hex SHA-1 of
  the UTF-8 source after `decode()` turns literal `\uXXXX` escapes into
  characters. `lookupTranslation` tries prefixes of 7, 10, 20 and 40
  characters, and the bundles ship 7. Check: `sha1("Cancel")` starts
  `77dfd21`, and es-ES `2fa_modal.77dfd21` is "Cancelar".
- **Fallback.** No namespace, no key, or `0`: the English source is shown.
  Misses are traced (1 in 1001 clients, `missingI18nString`). Nothing falls
  back to another locale: en-GB has its own bundle.
- **en-US.** `t()` returns the source untouched when it has no `{`.
  Otherwise the source is formatted like any translation.
- **Format.** `new MessageFormat(text, locale).format(args)`, with
  format-message (vendors YZtm/BYkh/2bDf) and no tag parsing. Supported:
  `{x}` (String(x)), `{x, number[, integer|percent]}`, `{x, date|time,
  style}`, `{n, plural, [offset:k] =0 {…} one {…} other {…}}` with `#`,
  `selectordinal`, and `select`. In plurals `=n` beats the category, then
  `other`. Quoting is ICU's: `''` is a quote, and `'{…}'` (or `'#'` in a
  plural) is literal. Plural categories come from Intl.PluralRules,
  numbers from Intl.NumberFormat(locale). What the es-ES and ja-JP bundles
  actually use: about 1450 `=1` plurals, 176 `one`, 136 `=0`, 13 `number`,
  a few `select` and `selectordinal`, one `date, long`, and about 1900
  strings with `<tags>`. `rt()` turns those tags into React elements.
- **CJK.** For ja-JP, zh-CN, zh-TW and ko-KR, `[[[…]]]` groups get U+2060
  word joiners between characters and U+200B around them, so lines break
  only between groups (`group_cjk`).
- **Locales.** `3t/7`: de-DE, en-GB, en-US, es-ES, es-LA, fr-FR, ja-JP,
  pt-BR, ko-KR, it-IT, zh-CN, zh-TW. Labels: "Deutsch (Deutschland)",
  "English (UK)", "English (US)", "Español (España)", "Español
  (Latinoamérica)", "Français (France)", "日本語", "Português (Brasil)",
  "한국어", "Italiano (Italia)", "简体中文", "繁體中文". The Language select
  (prefs-dialog `LocalePref`) sorts them by label and is disabled offline
  ("Go online to change your language."). `<html lang>` is es-419 for es-LA.
- **Writing the pref.** `KQBi setLocaleForTeam({locale, teamId})`:
  1. `LTu3 setLocale`: localConfig `user_locale`; ensure the bundle; set
     `<html lang>`, dayjs and moment; run the locale callbacks (a re-render).
  2. `setUserPrefByApi({pref: "locale"})`, i.e. users.prefs.set, applied
     optimistically.
  3. Then, in the Sonic client (`data-app` "client"/"client-v2", which is
     the desktop app), `refetchLocalizedApis` (custom status presets and
     other localized APIs). Older clients reload instead.
  4. It also writes an `i18n_locale` cookie for slack.com, valid 365 days.

  So the desktop app switches **live**, with no reload.
- **Dates and numbers** aren't in the bundles. They come from dayjs/moment
  locale data (dayjs's own locales, with Slack's overrides on top), Slack's
  `Azem` tables, and the formatters `tNjd formatDate` (tokens
  `{date_long_pretty}`, `{time}`, …), `YvgU` (day divider), `2Ie3`
  (calendar date), `xiXI` (time), `zZAT` (time ago) and `bRXt` (Today and
  Yesterday: the first word of `calendar()`). Examples: German times are
  "15:04 Uhr", French "15 h 04", pt-BR "15h04". de, es, fr, it, ja and pt
  have no 12-hour format. en-US, en-GB, ko-KR, zh-CN and zh-TW default to
  12 hours (`wrON`).
- **Time zones.** Slack ships a localized zone list per locale in JS
  (`sbu9`, `i["es-ES"] = [["(UTC-11:00) Islas Midway, Samoa Americana",
  "Pacific/Midway"], …]`).

## Clack

`internal/i18n`:

- `bundles.go` pins build a84662d2d135's translationMap file names (they are
  content hashes, so a cached copy never goes stale) and fetches them from
  the CDN with no cookie and no token. The fetch goes through `tlsfp.Client`,
  since Go's own TLS must never talk to Slack. Bundles are cached under
  `<user cache>/clack/i18n/<file>`. Clack ships no translated Slack strings:
  only the English sources, which are the keys.
- `catalog.go` holds the key scheme and the `0` handling. `i18n.go` holds
  `NS("prefs").T(src, "name", v)`, the active locale (an atomic snapshot
  with a per-locale message cache), `SetLocale` (loads on a goroutine and
  never blocks the UI), and `OnChange`, which the UI uses for Invalidate.
- `msgfmt.go` is the format-message subset above. `plural.go` has the CLDR
  42 rules for the 12 locales. golang.org/x/text/feature/plural is CLDR 32,
  which lacks the `many` category fr, es, it and pt now have for exact
  millions, so Clack doesn't use it. `number.go` has Intl.NumberFormat's
  separators and es's minimumGroupingDigits of 2 ("1234", "12.345").
- `dates.go` and `timeago_tables.go` hold the dayjs locales and Slack's
  tables, plus the functions `DayDivider`, `Time`, `ShortTime`,
  `CalendarDate`, `RelativeDay`, `LongDatePretty` and `TimeAgo`.
- `rich.go` is `rt()`: `NS.RT(src, args…)` formats the translation, reads
  its tags the way C91c's textToDomJson does (`<tag>…</tag>`, with an
  optional `class`/`className`), and only then puts the values in, so a
  name with `<` stays text. Each `Part` has its text, its innermost tag
  and class, and the placeholder it came from, which is how a surface
  finds where `{msg}` or `<a>` sits in the locale's word order. `Listify`
  is nTGe's listify ("A, B, and C"; "A y B" in es-ES; "A、 B" in ja-JP),
  with "and"/"or" from the general namespace.

On the UI side, a menu row of Slack's text is `MenuItem{…}.In(ns)`
(popups/i18n.go): the label is drawn translated and the row's template
key stays its English label's (`LabelKey`), so plugins find rows by the
same key in every locale. Code that picked rows by label now picks them
by key.

The bundle names are pinned instead of discovered because discovering them
means loading Slack's client page, and Clack never loads Slack web pages
(see docs/SIGNOUT-AUDIT.md). A newer Slack build only adds strings. Strings
Clack wires that are missing from the pinned bundles show in English, the
same fallback Slack itself uses.

The localized time zone lists are Slack's too, but Slack ships them in
JS (sbu9), not in a bundle. Clack carries them generated
(internal/core/tz_slack_locales.go), as it already carried the en-US list.
The date tables in `dates.go` and `timeago_tables.go` are carried the same
way.

## Wiring

Each wired string looks up Slack's own key in the namespace Slack's
component uses. The namespace was read from the `X = new I18n("ns")` that
the call site's `X.t(…)` belongs to (an index of every call site in
build 4d0c78085232's chunks: string, namespace, module, function).

  Slack shows none of these, so they're listed, not translated.

  "Workflows" (from the client namespace) and Clack's "aren't supported"
  toasts, "No apps", the people filter's "Anyone", the filter menu's
  "to navigate / to select / to dismiss", `Search "q" in #channel`.
- The desktop shell's own menus (Copy Link, Open Link, Copy Image, Copy
  Image URL, Copy Email Address, and the spellcheck menu's Cut / Copy /
  Paste / Add to Dictionary): Slack's Electron shell translates those
  itself, not through the web client's bundles.
- Emoji names stay canonical (":tada:"): Slack's tooltip runs them through
  convertEmojiInStringToLocalized, a per-locale emoji name map that isn't
  in the bundles.
- The status presets ("Commuting", "Out sick", …) come from Slack's API,
  which localizes them server-side (refetchLocalizedApis); Clack's
  fallback list is English. `{status_expiration}` and the OOO reply's
  dates use CalendarDate and the time outside en-US: tNjd's Azem formats
  for them aren't ported.
- The search autocomplete's value names (in:, is:, has:, type:, during:):
  they double as the query's syntax (type: takes its label lower-cased),
  so they stay the modifiers' English.
- The search filter pill "From Ann" puts the translated word before the
  name; Slack draws the name with an avatar, without a string.
- In Preferences, the strings `internal/ui/i18n_unkeyed_test.go` lists.
  Theme and font names are ones Slack doesn't translate either. The rest
  are Clack-only rows (the updater, live updates, Troubleshooting) or text
  Clack words differently from Slack, or builds from parts where Slack has
  one string with a tag or a placeholder (the shortcut lines, the privacy
  page, "Messaging defaults").

Clack-only UI keeps English: the updater ("Check for Updates…"), plugins
(Taut, Slick), "Not available in Clack yet", live updates, and
diagnostics.

## Tests

- `internal/i18n`: the key scheme, fallback, the 0 entries, the
  MessageFormat subset (plural with =n, offset, #; select; selectordinal;
  quoting; tags left alone), plurals, numbers, dates in 9 locales, the
  loader's cache and SetLocale. `TestSlackBundles` checks Slack's real
  es-ES and ja-JP bundles (`CLACK_I18N_NET=1`).
- `internal/ui`, "no English left": `TestPrefsNoEnglishLeft` draws every
  Preferences page in en-US and in es-ES and ja-JP. A string drawn
  unchanged fails if Slack's bundle translates it, or if no namespace has
  it and it isn't on the list in i18n_unkeyed_test.go.
  `TestMainNoEnglishLeft` does the same for the sidebar, rail, top bar and
  a channel through `theme.DrawHook`, then for each menu, dialog and
  search surface (`i18n_surfaces_test.go`: message ⋮ and right-click,
  channel ⋮, sidebar row, section ⋯ and right-click, bell, Advanced
  settings, Forward, Delete, emoji picker, status, workspace and user
  menus, switcher, results page), each built fresh in the locale. There,
  only strings Slack translates fail, because the account's own data is
  drawn the same in every locale. `TestReactionTipLocale` (messages) and
  `TestRT` / `TestListify` (i18n) check ja-JP's word order with
  bundle-shaped strings.
  `TestLocalePref` covers the pref: users.prefs.set, ui.json, the live
  switch.
- `.github/workflows/i18n.yml` runs all of the above against the CDN
  bundles (cached) and saves `TestLocaleShots`: the client, two
  Preferences pages and every surface above, in es-ES and ja-JP, with
  fonts-noto-cjk for the Japanese fallback.
