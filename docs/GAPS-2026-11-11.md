### How it's counted

`python3 -I docs/gaps/score.py [ref] [-v]` re-runs the count at any commit.
`-v` prints every open check. The method is the roadmap's, found in its
session log, because the repo never recorded it:

- **Base.** In the 593 this was a hand count of 279 checks: every row of the
  Prefs, Channels, Files and Views audits, Views' "Not done" bullets, the 25
  plugins in the bench, and each distinct "isn't supported yet" toast in the
  code (each toast counts as a failed check). The script counts the same
  sources. A row is open when its status says open, partial, missing, not
  done, greyed (other than "Greyed: none") or still different. It lists the
  handful of rows where that reading is wrong (the verb "open", say).
- **Audits.** These are the rows of the Search, Messages, Huddles and
  Composer audits with a bold status. Matched and fixed pass. Open, partial
  and missing fail.
- **Why 622, not 593, at 3a5a037.** The audit half matches: the script
  finds the roadmap's 314 status rows there. The base doesn't. The roadmap
  hand-trimmed it to 279 (Prefs 104, Channels 60, Files 24, Views 30), and
  the script counts every row, 308. The script also widens the toast grep to wordings the
  roadmap's `supported yet|available yet|in Clack yet` missed: "… in
  yoloslack", "… here yet", "… on this platform yet", and the create menu's
  `unavailable("…")` rows.

## The gaps, most visible first

The ranking is how often someone who uses Hack Club Slack all day on macOS
would hit each gap. Size: **S** is under an hour, **M** is 1–3 hours, **L** is
more than one agent session. "Slack" cites the module that does it in CDN
build 4d0c78085232 (or the audit row that cites it).
