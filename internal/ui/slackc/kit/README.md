## api.elements components (internal/ui/slackc/kit)

In Taut, `this.api.elements.Button` and the rest are Slack's own React components. In Clack, the JS side renders each one as a host node `{"t":"@","n":"<SlackComponentName>","p":props,"c":children}`, and `kit` draws a native look-alike with Clack's theme, icons and popups. `kit.Register()` (idempotent) registers every component below with `slackc.RegisterHost`. The ui root calls it once, before plugins render.

The prop contract is the `*Props` types in taut's `app/api/elements.ts` (for RichTextInput, `app/slack/richTextInput.tsx`). Handlers get DOM-like event objects where React would pass one: `{type:"click", button, clientX, clientY, altKey, ctrlKey, shiftKey, metaKey, …}` for clicks, `{type:"change", target:{value, checked, id}}` for inputs, and `{type:"keydown", key, code, target:{value}, …}` for keys. Coordinates are window CSS px.

Shared mechanics:
- **Window coordinates.** Gio has no absolute transforms. A component learns its window origin from pointer events: `Env.PointerWin()` minus the local pointer position, the way `ui.originTracker` does. Floating layers (Popover, custom MenuTrigger menus) also track pointer moves over the whole window while open, so an origin that was never hovered gets corrected on the first move.
- **Floating content that stays in the host tree** (Tooltip tips, Popover children) is recorded during the host's own layout and drawn above everything with `op.Defer`. It never runs a host-tree layout from inside a later overlay.
- **Menus** go through `popups.Menu` (keyboard navigation, submenus, flipping at the window edges) via an `Env`-backed `popups.Host` adapter.
- **Icons.** `clackIcon` maps Slack icon names to Clack icons: the exact name, then an alias table, then the name without `-filled`/`-outline`/`-small`…. Anything else falls back to a quiet dot, never icons' red "missing" box.

### Not registered (and why)
- **Tabs** (Preferences' tab list), **HelpButton**, **ComposerLinkModal**: taut's app *patches* these (`patchComponent`) rather than rendering them as elements. They belong to their native owners' `slackc.Render` call sites, where `<Original>` calls back into the native widget.
- **WysiwygContainer**, **texty_input_with_autocomplete**: taut's own RichTextInput renders these around Quill. Clack's JS side renders `RichTextInput` as one host node instead, since kit's RichTextInput is the whole field. A plugin rendering texty directly would need ref access (`getContents()`), which host nodes don't have.

### Suggested follow-ups outside kit
- `Host.WindowRect()` from the layout engine, which already computes window boxes for `SetRects`. It would replace the pointer-learned origins and fix Popover placement before the first pointer move.
- The window size on `Host` (slackc has `windowSize`), so Popover and Tooltip can flip at the window edges.
- Exported date and time pickers in popups (`dtDate`/`dtTime` are unexported). kit has its own calendar and time list that copy their look.
